# Rebuild prompt: interactive learning-game platform

You are a senior full-stack engineer. Build from scratch an interactive learning-game platform for secondary students. This pass covers only the platform itself: the subject catalogue, the game list, game playback, a bilingual interface, and a way for future games to report scores.

Do not design, implement, or list any specific learning game in the catalogue. Do not write gameplay, questions, characters, songs, or levels. When a game is added later, it only needs one HTML file plus one catalogue entry.

Interface copy is in Traditional Chinese and English. Code comments and source code are in English. Do not show a specific school name, school domain, or school badge on any screen, in any copy, in any domain, or in default data. Make the display name a configurable constant. The default name is **PlayLab**.

The platform does not need accounts. Scores exist only on this device. Do not build login, a backend, or a database.

---

## 1. Product

PlayLab is a website. A student chooses a subject, then a game. The game opens in an iframe on the page. The platform handles browsing, instructions, full screen, language, and collecting scores. Game content is added later and is out of scope this time.

Situations:

1. Class: a student opens the platform and goes to the assigned subject and game.
2. Homework: a student replays on a phone. The score stays on that device.
3. On-device scores: the leaderboard can show this academic year, all time, this month, and class (when class data exists).
4. Independent study: filter the game list by topic and year group.
5. Adding content: a new game is one static HTML file plus one catalogue entry.

## 2. Technology

- Vite 5 + React 18 + TypeScript (strict) + React Router 7 + Tailwind CSS 3.
- A game is not a React component. Its path is `public/games/{subject}/{gameId}/index.html`. The platform loads it in an iframe. Do not put learning games in this folder this time.
- Scripts: `npm run dev`, `npm run build`, `npm run preview`.
- Static hosting. `public/_redirects` contains:

```

```

## 3. Routes

Providers, outer to inner: `LanguageProvider` → `GameProvider` → `BrowserRouter`.

| Path | Page |
| --- | --- |
| `/` | Home, with 17 subject entries |
| `/subject/:subject` | That subject’s game list and filters |
| `/game/:subject/:gameId` | Game details, iframe, and on-device scoreboard |
| `/profile` | Play history on this device |

An unknown subject still opens the subject page and shows an empty state. An unknown game says it cannot be found and links back to that subject.

Language is stored in `localStorage` under `playlab-lang`, with values `en` or `zh`. The default is `en`. In English the toggle shows 「中文」. In Chinese it shows 「EN」. The choice survives a reload.

The header has a language toggle and a way back to the home page. Breadcrumbs: home is 「主頁」. A subject page is 「主頁 / subject name」. A game page is 「主頁 / subject name / game name」.

## 5. Page behaviour

### 5.1 Home

17 subject cards, in this fixed order: Chinese, English, Mathematics, Physics, Chemistry, Biology, Science, Geography, History, Chinese History, Economics, BAFS, Music, Physical Education, Tools, AIoT, Others. Each card links to `/subject/{id}` and shows the subject name and a short description. Below that is the three-step 「使用方式」 section. The layout must work on phones and desktops, with no horizontal overflow.

### 5.2 Subject page

Title and subtitle. When the subject has games, show filters: topic, year group, clear, and the count. Topics come from `topic`, deduplicated and sorted. Year groups come from `difficulty`. That field stores a year-group string such as `S1`, `P2`, or `S4 - S6`, not Easy／Medium／Hard.

A game card shows title, description, topic, duration, year group, and author. Show a cover when one exists. Mark `leaderboard: true` as having a leaderboard. A game with `externalUrl` opens in a new tab and is labelled 「外部」. Show an empty state when there are no games, and a different empty state when filters match nothing.

### 5.3 Game page

The user can return to the subject and enter full screen. The page shows title, description, subject, difficulty, time, and author.

Centre the game frame. It must not exceed the screen. While loading, show 「正在載入遊戲」. The iframe:

- `src` is `/games/{subject}/{gameId}/index.html`
- `sandbox="allow-scripts allow-same-origin allow-forms allow-downloads"`
- `allowFullScreen`
- title is the game name

Full screen: other browsers use the iframe’s native full screen. iOS and Safari use a fake full screen that fills the viewport, can be exited, and locks page scrolling. If the catalogue sets `touchSafe: true`, stop touch scrolling from interfering with the game.

When leaving the game page, the parent sends `{ type: 'playlab:requestScore' }` to the iframe.

Do not use an iframe for a game that has `externalUrl`. Show the description, an open link, and a way back.

When `leaderboard: true`, show the leaderboard under the iframe. When `leaderboardMode: 'tracks'`, use a track leaderboard: the same game can rank separately by track and difficulty. Metadata is for display only and does not add another ranking rule.

### 5.4 Profile

Read records in localStorage whose score is greater than 0, newest first. State that these records belong to this device. Paginate the list, 10 rows per page: game name linking to the game page, subject, local time, and score. When there are no records, show an empty state and 「瀏覽遊戲」. Dates use the user’s local calendar day.

## 6. Catalogue, playback API, and on-device scores

### 6.1 Catalogue data

`GameProvider` uses one array as the catalogue. Do not build an admin backend. The array is empty except for one allowed test entry (see 6.4). Do not fill in real games.

```ts
{
  id: string
  title: string
  titleZh?: string
  description: string
  descriptionZh?: string
  subject: string
  difficulty: string
  estimatedTime: string
  author?: string
  thumbnail?: string
  topic?: string
  externalUrl?: string
  leaderboard?: boolean
  leaderboardMode?: 'default' | 'tracks'
  scoreLabel?: string
  touchSafe?: boolean
}
```

The Chinese interface prefers `titleZh` and `descriptionZh`. Provide: all games, games by subject, one game lookup, the topic list for a subject, and the year-group list for a subject.

### 6.2 Score messages

If a game records a score, it posts to the parent:

```js
window.parent.postMessage({
  type: 'playlab:score',
  subject: '<subject>',
  gameId: '<gameId>',
  score: 1234,
  metadata: {}
}, '*');
```

Rules:

- `score` must be a finite number. Higher is better. Do not store 0 or negative scores.
- `subject` and `gameId` must match the current route.
- Accept messages only from that iframe’s `contentWindow`.
- For the same dedupe key, keep a score only when it is strictly higher. Use `__default__` when there is no special key. If metadata has `trackId`, the dedupe key is `trackId` plus `difficulty`.
- The game should listen for `playlab:requestScore`, `pagehide`, and `beforeunload`. Do not treat switching tabs as the end of play.
- Metadata is not used for ranking. It is only shown on the track leaderboard.

The `localStorage` key `playlab-scores` is an append-only array. Each item has `id`, `subject`, `gameId`, `score`, `metadata`, and `createdAt`. Do not build a UI to delete or edit scores. All score writes go through one function.

### 6.3 Leaderboard

The user can switch among this academic year, all time, and this month. When this academic year is selected, the user can choose the year. Academic years use Hong Kong time, from 1 September to 31 August of the next year, listed from 2025–2026 through the current year. This month uses the user’s local month.

Extract a class from the display name with `\b([1-6][A-Z])\b`, for example `5E`. If local records have no such name, do not show the class filter.

Show the top 10 by default, with a way to expand all. Ties keep the earlier score first. If the user’s best score is not in the list, show an extra row at the bottom. Empty-state copy depends on the period and the class. Data comes only from this device.

### 6.4 The only allowed test page

To check the player page and the score API, you may add one placeholder with no learning content at `public/games/tools/score-check/index.html`. The screen shows only the platform name, a number, and two buttons: 「加 10 分」 and 「送出分數」. Sending posts the current number as specified in section 6.2. Register only this one catalogue entry, subject `tools`, `leaderboard: true`. Do not present it as a teaching game, and do not add a second game.
